# 图片与招聘海报

## 操作

- 生图：`根据内容，生成一张校招宣传长图`，换行后粘贴完整招聘正文。支持常见生图句式；不确定时用 `/生图 描述`。
- 招聘海报：包含招聘/校招和长图/海报的请求，且有换行正文时，使用程序模板排版。正文逐字排版，不使用模型生成文字或证书。正文第一条 HTTPS 链接用于二维码，请把投递链接放在其他链接前面。
- 同条消息替换 Logo：发送新 Logo 图片并附上 `替换海报上的 Logo`，使用当前对话最近一张已保存图片为目标、新图片为素材。
- 分步替换 Logo：先发送 Logo，收到保存确认后说 `把海报上的 Logo 替换成我发你的这个 Logo`。使用最近上传图片和最近生成图片。
- 其他修改：`修改这张图，修改要求`；选择旧版用 `/图片` 和 `/改图 #编号 修改要求`。

## 范围与限制

- 模板当前只有简洁蓝色校园招聘版式，Logo 在顶部固定区域，文字保留源文件。支持模板 Logo 精确替换；其他自然语言布局/文字修改仍由图片模型执行，不保证保持原文。多个候选图片应主动使用编号指定。
- 常见明确操作可直接分流；OpenRouter 下其余文字任务使用当前文字模型返回 JSON 判断问答、生图、改图或澄清。模型推荐图片编号必须在当前员工当前对话候选列表内，程序再次校验；原文保留，转换图片任务时重新检查图片及全局额度。每个此类任务增加一次语言模型调用。模型意图判断仍可能有歧义，支持显式命令确定操作。
- 非模板图片的双图编辑通过 OpenRouter 两个 input_references 完成，模型修改范围与文字准确性需要查看输出；直连适配暂不支持双图。
- 机器人不校验链接是否有效或属于官方站点，请核对并用钉钉扫码验收。未提供链接时不画二维码。
- 模板中文字体使用 Windows 微软雅黑或容器文泉驿，也可通过 POSTER_FONT 环境变量指定字体文件。
- 钉钉返回的已验证 OSS HTTP 地址升级为 HTTPS 请求；其他未知 HTTP 地址仍拒绝，不跟随重定向。上传失败会终止同条消息的依赖改图，保留原图，只发送一次失败提示。

## 验证

自动测试覆盖双图顺序、来源归属、模板源文保留、上传失败停止依赖改图和招聘请求分流。已实测原 Logo 下载通过 HTTPS；未对旧失败任务自动重试、未产生额外模型调用。真实双图修改仍需在钉钉重试验收。
