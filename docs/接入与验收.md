# 接入与验收

**当前已改用 OpenRouter。** 第 2 节是保留的 OpenAI 官网直连说明；本机请按 [OpenRouter 接入](OpenRouter接入.md) 填写 `OPENROUTER_API_KEY`。钉钉创建、员工白名单和验收步骤继续适用。

## 1. 创建钉钉企业内部应用

在 [钉钉开放平台](https://open.dingtalk.com/) 创建企业内部应用，添加机器人能力，名称可设为“企业 AI 助手”，接收模式选择 Stream。首批应用可见范围只放自己和少量试用人员。

创建步骤以官方后台为准：[创建机器人应用教程](https://opensource.dingtalk.com/developerpedia/docs/explore/tutorials/stream/bot/python/)。应用发布后校验单聊消息是否带有企业员工 `senderStaffId`。本服务不会用昵称或任意前端输入替代企业身份。

把以下内容填写到本机 `.env`，不要发到聊天、Git 或截图中：

| 字段 | 来源 |
|---|---|
| `DINGTALK_CORP_ID` | 企业 CorpId |
| `DINGTALK_CLIENT_ID` | 内部应用 AppKey / Client ID |
| `DINGTALK_CLIENT_SECRET` | 内部应用 AppSecret / Client Secret |
| `DINGTALK_ROBOT_CODE` | 机器人 RobotCode；按后台提供的值填写 |

根据后台权限配置，确保应用可以接收机器人消息、发送人与机器人单聊消息、下载机器人收到的图片、上传媒体。首版不要求同步全量通讯录，也不处理群聊消息。

接口资料：[官方 Python Stream SDK](https://github.com/open-dingtalk/dingtalk-stream-sdk-python)、[接收消息](https://opensource.dingtalk.com/developerpedia/docs/learn/bot/appbot/receive/)、[发送消息类型](https://open.dingtalk.com/document/orgapp/types-of-messages-sent-by-robots)、[上传媒体](https://open.dingtalk.com/document/orgapp/upload-media-files)。

## 2. 配置 OpenAI

在 `.env` 填写项目 API Key：

```dotenv
TEXT_API_KEY=在本地填写
IMAGE_API_KEY=在本地填写
```

可以填写同一个有相应权限的项目密钥。模型名和地址已提供初始值：

```dotenv
TEXT_BASE_URL=https://api.openai.com/v1
TEXT_MODEL=gpt-4.1-mini
IMAGE_BASE_URL=https://api.openai.com/v1
IMAGE_MODEL=gpt-image-2
IMAGE_EDIT_FORMAT=json
```

初次先保持 `PROVIDER=mock`，验证钉钉文字、模拟图片往返。确认正常后，再改成 `PROVIDER=openai`，重启 worker 和 sender/stream，并用非敏感的测试描述验证真实模型。

`TEXT_EXTRA_JSON` 和 `IMAGE_EXTRA_JSON` 可传模型支持的额外参数。当前图片服务契约要求同步返回 `data[0].b64_json`；不自动下载模型返回的任意 URL，不自动切换供应商。

本机已通过 OpenRouter 的真实文字、生图和改图调用；直连 OpenAI 及目标服务器网络尚未验证。实际验证范围见《验证记录》。

## 3. 只开通自己的员工账号

取得本人企业员工 userid（不是昵称或手机号），在项目目录执行：

```powershell
.\.venv\Scripts\python.exe -m app init
.\.venv\Scripts\python.exe -m app user --corp 企业CorpId --staff 本人员工userid --name 自己的名字 --text-limit 20 --image-limit 3
.\.venv\Scripts\python.exe -m app check
```

同时检查钉钉应用的可见范围包含自己。白名单是服务端第二层限制：仅把员工加入钉钉可见范围，不会自动开通模型调用。

## 4. 启动本机服务

在三个终端中分别执行，保持它们运行：

```powershell
# 终端 1：模型任务 / 图片下载
.\.venv\Scripts\python.exe -m app worker
```

```powershell
# 终端 2：结果及受理提示投递
.\.venv\Scripts\python.exe -m app sender
```

```powershell
# 终端 3：接收钉钉消息
.\.venv\Scripts\python.exe -m app stream
```

管理可使用 CLI，或者另开终端运行 `python -m app serve`。本机暂停/休眠会中断服务；多人正式试用前部署到常开服务器。

Stream 连接由服务主动发起。出站网络应允许钉钉 Stream 和 API 服务，以及所配置的模型服务；无需让每位员工配置模型网络连接。[Stream 常见问题](https://opensource.dingtalk.com/developerpedia/docs/learn/stream/faq/)

## 5. 验收顺序

1. 给机器人单聊发送 `/帮助`，确认收到指令说明。
2. `/新对话 验收通知`，随后发“请写一份下午三点的培训通知”。
3. 再发“缩短为三句话”，确认使用当前会话上下文。
4. `/新对话 验收海报`，`/生图 蓝色几何背景，无文字`，确认先有受理提示再有图片。
5. 发送 `修改这张图，右下角增加留白`，确认收到修改后的图片；用 `/图片` 查看保留的版本编号。修改更早的图片仍可用 `/改图 #编号 修改要求`。
6. `/图片` 查看来源关系；`/看图 编号` 验证能重发旧版本。
7. `/搜索 下午三点` 找回通知；`/继续 会话编号` 后继续修改。
8. 归档通知会话，确认从最近列表收起，关键词搜索仍可找回。
9. 开通第二位测试人员，用相同关键词搜索；确认看不到第一位的记录，也不能用第一位的会话/图片编号访问。
10. 将测试人员文本额度调为 1，连续提交两次，确认超限任务不进入模型队列。
11. 检查 `tasks` 与 `deliveries`，确认模型成功和钉钉投递状态分别保存。

真实生图、改图每次可能产生费用，因此先用模拟模式验证权限和消息流程。修改图片效果、长回复在钉钉手机/电脑上的显示、接口限流仍要人工验收。

## 常见情况

| 现象 | 排查 |
|---|---|
| 找不到机器人 | 应用发布、可见范围、企业组织是否正确 |
| 没有任何回复 | stream 与 sender 是否都在运行；本人是否在服务端白名单 |
| 有受理提示但无结果 | worker 是否运行；用 `/任务 编号` 查询 |
| 显示结果待核查 | 请求超时或执行中断；不要连续重复生成，先查供应商记录 |
| 任务成功但没收到图片 | 查看投递失败记录；媒体上传权限、单聊发送权限、文件尺寸 |
| 图片下载域名不匹配 | 核实钉钉实际返回的合法文件域名后配置允许列表；不要直接放开所有地址 |
| 管理接口 401 | 填写本机 `.env` 的 `ADMIN_TOKEN`；员工无需此令牌 |
| 模型返回不支持参数 | 核对模型名和其官方接口参数；调整 `*_EXTRA_JSON` 或适配代码 |
